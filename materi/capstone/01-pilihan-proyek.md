# Capstone — Pilihan Project

Pilih SATU dari tiga pilihan. Pertimbangkan: kebutuhanmu, waktu, dan apa yang ingin kamu buktikan. Tidak ada pilihan yang "lebih mudah" — semuanya menantang dengan cara berbeda.

---

## Pilihan A — Bangun dari Nol

**Tugas**: Bangun aplikasi baru dengan **3+ fitur inti** + **minimal 1 integrasi third-party** yang benar-benar berfungsi.

### Syarat minimum
- ✅ Product brief (Modul 0.5) ditulis & disimpan sebagai `BRIEF.md`
- ✅ 3+ fitur inti dari brief, semua berfungsi
- ✅ Minimal 1 integrasi: API pihak ketiga / webhook / database eksternal / bot notification (Modul 3-4)
- ✅ Git history: commit per fitur dengan pesan jelas
- ✅ README: apa, cara install, cara pakai
- ✅ Tidak ada secret di repo

### Ide (atau buat sendiri)
- Aplikasi catatan dengan sinkronisasi cloud
- Aplikasi pengingat yang kirim notifikasi via Telegram
- Pelacak pengeluaran dengan laporan otomatis
- Aplikasi "cek harga" yang ambil data dari API publik

### Skala yang benar
Terlalu kecil = 2 fitur sederhana (kurang bukti). Terlalu besar = 10 fitur yang semuanya setengah jadi (terlihat dari git history yang berantakan). Target: **3-5 fitur yang solid, selesai, teruji**.

## Pilihan B — Kontribusi Open Source

**Tugas**: Ambil project open-source yang menarik → pahami (Modul 2.1) → tambah fitur/perbaiki bug yang *meaningful* → buka **Pull Request**.

### Syarat minimum
- ✅ Pilih project: punya issue bertanda `good first issue` / `help wanted`
- ✅ Dokumentasi eksplorasi di `PETA.md` (arsitektur, entry point, alur)
- ✅ PR dibuka: perubahan jelas, fokus satu masalah, mengikuti panduan kontribusi project (CONTRIBUTING.md)
- ✅ PR punya deskripsi: masalah → solusi → cara test
- ✅ Kamu bisa menjelaskan codebase itu

### Kenapa ini bagus
- Pengalaman bekerja di codebase orang lain — langsung di dunia nyata (Modul 2 penuh)
- Feedback dari maintainer = pembelajaran paling otentik
- Portfolio di GitHub publik

### Catatan realistis
- PR tidak dijamin diterima — yang dinilai adalah **proses & kualitas** (panduan kontribusi diikuti, test ditulis, perubahan rapi)
- Pilih project yang aktif & ramah pemula. Cari di GitHub: `label:"good first issue"`
- Kalau PR ditolak: refleksikan alasan penolakan → perbaiki → itu bagian pembelajaran
- **Hati-hati**: jangan spamming PR berkualitas rendah — pahami isu "AI-generated contributions" yang membebani maintainer (lihat REFERENSI.md). PR-mu harus menunjukkan pemahaman, bukan sekadar "generated by AI".

## Pilihan C — Chatbot Multi-Fungsi Nyata

**Tugas**: Bangun chatbot yang **benar-benar dipakai untuk kebutuhan nyata** — bukan demo. Gabungkan otomasi + analitik (Modul 3) dengan minimal 1 integrasi eksternal (Modul 4).

### Syarat minimum
- ✅ Melayani masalah nyata (milikmu/keluarga/teman/komunitas)
- ✅ Otomasi: minimal 1 tugas terjadwal + perintah nyata (tool calling)
- ✅ Analitik: menjawab pertanyaan dari data, tidak mengarang (anti-halusinasi terverifikasi)
- ✅ Production-ready (Modul 3.5): logging, retry, rate limit, session persist, secret aman
- ✅ Integrasi: minimal 1 layanan eksternal (email, payment, storage, dsb)
- ✅ Uji ketahanan: 5 chaos test (Modul 4.5) didokumentasikan

### Contoh kebutuhan nyata
- Bot reminder & laporan untuk warung/UMKM (data penjualan harian)
- Bot informasi untuk grup komunitas/kelas
- Bot personal: catatan, task, ringkasan dokumen
- Bot yang memonitor sesuatu (harga, status, jadwal) dan memberi alert

### Yang membuat ini istimewa
Bot yang **dipakai sungguhan** akan menghadapi input tak terduga, kebutuhan yang berubah, dan user non-teknis — semua adalah pelajaran. Di akhir, mintalah 1-2 orang lain memakainya dan catat feedback-nya di refleksi.
