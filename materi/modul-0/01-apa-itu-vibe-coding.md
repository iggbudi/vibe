# 0.1 — Apa itu Vibe Coding

**Durasi**: 1 hari (±2 jam)
**Tujuan pembelajaran**:
- Menjelaskan definisi vibe coding dan sejarah singkatnya
- Membedakan vibe coding dengan coding tradisional
- Mengetahui kekuatan, batasan, dan kapan tepat digunakan

---

## Definisi

**Vibe coding** adalah cara membuat software dengan mendeskripsikan apa yang kamu mau dalam bahasa sehari-hari ke AI (LLM), lalu AI menuliskan kodenya. Kamu mengarahkan, mengetes, dan memberi umpan balik — bukan mengetik kode baris per baris.

Istilah ini diciptakan **Andrej Karpathy** (co-founder OpenAI, mantan kepala AI Tesla) pada **Februari 2025**. Dia menggambarkannya sebagai:
> *"Fully give in to the vibes, embrace exponentials, and forget that the code even exists."*

Pendekatan ini berakar dari klaimnya tahun 2023: *"the hottest new programming language is English"* — bahasa pemrograman terbaru adalah bahasa Inggris (atau bahasa manusia mana pun).

**Fakta menarik**: "Vibe Coding" terpilih sebagai **Word of the Year 2025** oleh Collins English Dictionary.

## Vibe coding vs coding tradisional

| Aspek | Coding tradisional | Vibe coding |
|---|---|---|
| **Menulis kode** | Kamu mengetik semua baris | AI menulis, kamu mendeskripsikan |
| **Peran utama kamu** | Menulis & memahami kode | Mengarahkan, mengetes, menilai |
| **Kecepatan prototipe** | Lambat (hari-minggu) | Sangat cepat (menit-jam) |
| **Pemahaman kode** | Mendalam (kamu yang tulis) | Bervariasi — harus dilatih |
| **Risiko utama** | Bug dari tulisan sendiri | Bug dari kode yang tidak dipahami |
| **Terbaik untuk** | Sistem kritikal, maintenance jangka panjang | Prototipe, tools pribadi, eksplorasi |

## Definisi yang diperdebatkan

Simon Willison (programmer & penulis terkenal) membuat garis tegas:
> *"Jika LLM menulis semua baris kode, tapi kamu me-review, men-test, dan memahaminya — itu BUKAN vibe coding, itu menggunakan LLM sebagai asisten mengetik."*

Kurikulum ini mengambil posisi **Willison**: vibe coding yang *baik* adalah yang tetap melibatkan pemahaman & review. "Vibe coding murni" (Accept All tanpa baca) hanya cocok untuk proyek sekali pakai (throwaway weekend project).

## Adopsi di dunia nyata

- **25% startup** batch Y Combinator Winter 2025 punya codebase 95% dihasilkan AI
- **Linus Torvalds** (pencipta Linux) menggunakan AI untuk menulis visualizer di project hobinya
- Perusahaan mulai mengadopsi untuk kasus komersial (WSJ, 2025)
- Tapi: studi METR (2025) menemukan tools AI **menambah 19% waktu** untuk developer berpengalaman di codebase besar & mature — AI tidak selalu mempercepat!

## Kapan vibe coding tepat?

| ✅ Cocok | ❌ Belum cocok |
|---|---|
| Prototipe & MVPs | Sistem keamanan-kritikal (medis, penerbangan) |
| Tools pribadi / internal | Codebase dengan compliance ketat |
| Otomasi tugas berulang | Infrastruktur yang harus 100% dipahami |
| Belajar konsep (dengan AI sebagai mentor) | Kode yang akan dirawat 10 tahun tanpa kamu |
| Eksplorasi ide cepat | Bug kritikal di produksi |

## Latihan (tanpa komputer)

1. Tulis definisi vibe coding dengan kata-katamu sendiri (2-3 kalimat)
2. Buat daftar: 3 hal yang ingin kamu buat dengan AI + untuk apa
3. Diskusikan (dengan diri sendiri atau teman): untuk masing-masing, apakah termasuk kategori "cocok" atau "belum cocok"? Kenapa?
4. Jelaskan posisi Simon Willison dalam 1 paragraf, dan di mana posisimu sendiri

**Output lesson ini**: pemahaman konsep + 3 ide project pribadi yang akan dipakai di modul-modul berikutnya.
